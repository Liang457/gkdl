# AGENTS.md

Rust async (tokio) multi-threaded downloader with an aria2/AriaNg-compatible JSON-RPC daemon and Windows system tray. Binary + library in one crate (`src/main.rs` + `src/lib.rs`).

## Commands

- Build release: `cargo build --release` → `target\release\gkdl.exe`
- Typecheck: `cargo check --all-targets`
- Test: `cargo test` (all pass in ~25s: lib unit tests ~3s, `tests/download_integration.rs` ~5s, `tests/rpc_integration.rs` ~16s)
- Single test: `cargo test rate_limit_slows_download`
- Format check: `cargo fmt --check`
- Lint check: `cargo clippy --all-targets -- -D warnings`
- No lint/fmt config exists; keep to default `cargo fmt`/clippy.
- CI (`.github/workflows/build.yml`) runs fmt → clippy → test → release build, **all with `--locked`**; pushing a `v*` tag additionally packs `gkdl.exe` into a zip and publishes it to GitHub Releases. keep `Cargo.lock` committed and updated whenever deps change (the version bump commits bump the lockfile too).

## Architecture

- `src/download/` — engine internals. `config.rs` holds `DownloadConfig` (split/slow/steal tuning + UA/Referer/header + `memory_threshold` + anti-crawler cooldown, defaults `min_split_size` 4 MiB, `steal_ratio` 0.4, `slow_ratio` 0.3, `slow_confirm` 3, `memory_threshold` 8 MiB, cap `MEMORY_THRESHOLD_CAP` 64 MiB, `cooldown_base_ms` 5000, `cooldown_max_ms` 60000); `curl.rs` is the HTTP transport (libcurl, `HttpClient` + `probe` + `stream_segment` + IDN punycode `normalize_url`, all via `spawn_blocking` + tokio channels; `CurlMsg::End` returns the `Easy` handle to the worker for cross-segment connection reuse); `engine.rs` probes (GET `Range: bytes=0-0`, never trust HEAD), chooses memory vs disk mode, and wires everything; `scheduler.rs` is the work-stealing scheduler (plus task-global 403/429 rate-limit cooldown state, atomics); `worker.rs` per-connection loop (consumes `CurlMsg` stream; parks the `Easy` handle across segments in `pooled`, waits out the cooldown before checkout); `detector.rs` slow-thread detection; `rate_limit.rs` global token bucket; `pwrite_writer.rs` preallocates the file and writes via offset `pwrite` (Windows `FileExt::seek_write`, Unix `write_at` — file-backed pages stay in the system cache, not the process working set, unlike the old whole-file mmap); `writer.rs` is the `DownloadWriter` trait + `MemoryWriter` (small files accumulate in RAM, `finalize` writes `.gkdl.tmp` + rename); `source.rs` multi-source failover; `segment.rs` segment bookkeeping. (`resume.rs` was removed — persistence now lives in `src/app/db.rs`.)
- `src/rpc/` — aria2-compatible JSON-RPC. `server.rs` routes HTTP POST / GET JSONP / WebSocket on `/jsonrpc`, plus `/` status page; `methods.rs` dispatches `aria2.*`; `protocol.rs` request parsing; `client.rs` is the CLI-side RPC client (`rpc::client::call`, libcurl POST via `spawn_blocking`).
- `src/app/` — application layer. `task_manager.rs` — `TaskManager` bridges engine and RPC: GID registry, status FSM, `broadcast` events → WS notifications, post-download hook, error → aria2 code mapping (`map_error_code`: 24 checksum, 2 timeout, 3 404, 6 network, else 1); `rehydrate_from_db` turns crash-leftover records into paused tasks (no auto-restart). `db.rs` — SQLite (`rusqlite` bundled) state store `%APPDATA%\gkdl\state.db`: `downloads` + `segments` tables, WAL mode, retention cleanup (default 7 days) for `complete`/`error` records. `logging.rs` — rotating file + stdout dual writer; archives stale logs at startup (tar.xz → gz → tar fallback). `config.rs` (YAML at `%APPDATA%\gkdl\config.yaml`, priority: defaults < file < CLI; `state` section holds `db_path`/`retention_days`), `hooks.rs` (two modes: daemon uses `hooks.txt` — one command per line, auto-created in config dir; CLI uses a single `--post-script`; subprocesses default to `CREATE_NO_WINDOW` silent execution via `hook.hide_window`), `hash.rs`, `tray.rs` (menu item "打开 AriaNG" links to `daemon.aria_ng_url` config), `cli.rs`. `mod.rs` declares the submodules. Note: `aria2.changeGlobalOption` (and the config store) writes accepted options straight back to `config.yaml` via `ConfigStore::save`.

## Conventions & gotchas

- **All comments, doc strings, and error messages are in Chinese.** Match this in new code.
- **注释口吻：精准、朴实、简短、描述。** 只写这段代码是什么、受什么约束、防什么后果；不写变更史/旧实现对比（那些归 git log 和本文件），不复述下一行代码；一般 1–2 行，块注释 ≤4 行。陈述约束用平铺直叙的「必须…否则…」，不用「注意！」「不得」「绝不」等告示口吻。测试注释写「守护什么行为/场景」（可用「守护：」前缀），不写「修复前如何」。术语统一：**段**（不：分片/碎片/切片）、**worker**（「线程」仅指慢线程检测与 curl 阻塞线程）、**冷却**（403/429 任务全局）与**退避**（段级指数）分工、**窃取**（不：偷取）、**daemon**（不：守护进程）、tokio **任务**（不：协程）；piece 仅用于 pieceLength 等协议字段语境，中文叙述用「分块」。
- Windows-only in practice (tray via `tray-icon`/`muda`/`winit`). HTTP client is **libcurl** via the `curl` crate, statically linked (`static-curl`, built-in curl 8.21.0 source) with the `http2` feature — TLS uses **Schannel** (system cert store, no CA bundle, 国内环境友好). The `http2` feature pulls in `libnghttp2-sys` (pure cc compile). Building needs a C toolchain on PATH (works on this machine); **no cmake, no OpenSSL** (rustls was removed with reqwest). IDN (中文域名) is handled by the `idna` crate in `normalize_url` (curl's threaded resolver has no IDN).
- All curl HTTP requests are run in `spawn_blocking` (the `curl` crate is sync), with callbacks bridged to tokio via channels; probe/worker read timeouts are enforced on the async side. Keep requests `Accept-Encoding: identity` for probes and segmented downloads — they must get raw bytes (no gzip/br decode). **Exception:** when `allow_compression` (default true) is set, single-connection whole-file downloads (`src/download/engine.rs` `should_use_streaming`: no Range / unknown size / `total < 2*min_split_size`) go through `HttpClient::stream_whole` which sends `Accept-Encoding: gzip, deflate`; libcurl auto-decompresses (static curl has zlib, no brotli/zstd), written via `StreamingWriter` (growable `.gkdl.tmp` + atomic rename). Such downloads cannot resume — pause/retry restarts from zero.
- **Anti-crawler stance** (32-thread tail downloads were tripping remote WAFs): worker `Easy` handles are pooled and reused across segments — `CurlMsg::End` carries the handle back from `spawn_blocking`, `worker.rs` parks it in `pooled` and re-sends it via `stream_*_warm` next segment (URL must match; fallback to fresh handle is always allowed). HTTP 403/429 triggers a task-global cooldown (`scheduler.rs` `hit_rate_limit`/`cooldown_remaining_ms`, config `cooldown_base_ms`/`cooldown_max_ms`, doubling while active, capped); every worker waits it out in `wait_cooldown` before checkout, and failed segments back off exponentially (500ms base in `record_failure` → `FailureAction::Retry { delay_ms }`). Keep new-request paths (checkout, steal, retry) going through `wait_cooldown`, and don't reintroduce per-segment `Easy::new()` without keeping the pooled path — that churn is what looked like a crawler.
- Config YAML is parsed with **`yaml_serde`** (0.10), not `serde_yaml`. (Historically was `serde_yml`; the switch happened in commit `cf8817a`.)
- `README.md` (Chinese) mirrors this architecture and lists every CLI/daemon flag — prefer it over `src/app/cli.rs` for flag semantics.
- aria2 RPC quirks (locked in by `tests/rpc_integration.rs`): missing `params` treated as empty array; wrong token → 1s delay then HTTP 400; `system.multicall` carries token per inner call, not top-level; `getVersion`/`getGlobalStat` are unauthenticated.
- Persistence/resume: all downloads store segment state in the SQLite `state.db` (`src/app/db.rs`), saved ~1s by the monitor; disk-mode resume requires `total` and `urls` to match the probe and the output file to already exist at full size (else restart). Memory-mode tasks restart from scratch after a process restart (data was only in RAM), but keep their DB record. `memory_threshold <= 0` disables memory mode entirely.
- **Work stealing** is the core algorithm: idle worker steals the slowest segment's tail 40%; slow thread (speed < 30% of median, confirmed 3×) is killed and its segment returned. Design docs in `doc/` (Chinese) — read `doc/design/多线程下载算法设计.md` and `doc/design/慢线程拖累问题的处理方式.md` before touching `scheduler.rs`/`detector.rs`.
- `scheduler.rs` deliberately uses `tokio::sync::Mutex` (not std) to avoid blocking runtime threads. Keep that.
- Integration tests (`tests/`) use a hand-rolled HTTP server in `tests/common/mod.rs` — HTTP/1.1 **keep-alive**（引擎的跨段连接复用依赖服务器不断开）、Range support、`/fail`/`/broken` 404 paths、ignore-range mode，另含故障端点 `/hang_download`（探测正常下载挂起）、`/truncated`（报全长只发 40%）、`/flaky`（每段只发 N 字节）、`/block`（先拒绝 N 次，状态码可配 403/429/500）、`/redirect`、`/nosize`、`/slow`。服务器记录每次请求的观测数据（连接号/method/path/Range/时刻）与累计连接数（`request_log()`/`connection_count()`），供测试断言「分段并行」「续传从已写字节处继续」「403/429 冷却间隔」「跨段连接复用（请求数 > 连接数）」等协议行为。Tests write artifacts to `%TEMP%\gkdl_it`. Don't expect real network.
- **Memory tuning** (verified empirically): disk writes go through `pwrite_writer.rs` so the daemon's working set does NOT balloon to the file size (old whole-file mmap showed ~350 MB peak for a 400 MB file; pwrite keeps peak ≤ ~17 MB). `StateDb` pins `cache_size=-2048` and `release_memory()` (`wal_checkpoint(TRUNCATE)` + `shrink_memory`) is called when a task reaches a terminal state and in the periodic cleanup; the monitor persists segments via `scheduler.segment_records()` (no `speed_history` clone) to avoid per-second heap churn. **Do NOT switch to mimalloc as the global allocator** — tested and rejected: it raised idle commit (11 MB vs 3.5 MB with the default Windows allocator) and leaked ~18 MB of commit per download, while the default allocator keeps commit flat (~7.5 MB after 3×400 MB downloads).
- `file.bin` (256 KiB) at repo root is a test artifact, **regenerated every `cargo test`**: `tests/rpc_integration.rs` `rpc_server_serves_aria2_methods` calls `aria2.addUri` with no options (no `dir`), so `TaskManager::add_download` resolves the relative filename against CWD (crate root); it's small enough to go through memory mode, so it's written atomically at the end. It's gitignored — don't commit it.
