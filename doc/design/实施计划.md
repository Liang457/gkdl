# GKDL 实施计划

> Rust 实现的多线程下载器（Windows 可用），带 aria2/AriaNg 兼容 JSON-RPC 服务与系统托盘。
> 依据 `doc/` 下五份设计文档：《多线程下载算法设计》《慢线程拖累问题的处理方式》《aria2 AriaNg 兼容 JSON-RPC 规范》《aria2 HTTP 多线程下载源码分析》《PCL2多线程下载算法分析》。

---

## 0. 目标与形态

- **双模式**：`gkdl <url>` CLI 直接下载；`gkdl daemon` 常驻后台提供 JSON-RPC 服务 + Windows 托盘。
- **v1 特性**：多线程 Range 切片、工作窃取/慢线程三层检测、断点续传（控制文件）、SHA-256 校验、令牌桶限速、下载后自定义脚本。
- **实现语言**：Rust 1.97，单 crate，异步基于 `tokio`。

## 3. 下载核心实现要点

**切片**（`engine.rs`）— 按《多线程下载算法设计》§4：
1. HEAD/无 Range GET 探测 `Content-Length` + `Accept-Ranges`；不支持 Range → 单流。
2. 预切 `total / split`，每段 ≥ `min_split_size`；`total < min_split×2` 不拆。
3. 预分配文件（`set_len`）+ mmap 映射；worker 直接写入映射区间，非重叠天然安全。

**工作窃取**（`scheduler.rs`）— 快线程完成自己段后：
1. 无主段？→ 正常分配。
2. 否则找 avg_speed 最慢段，`remaining > 2×min_split` 才从尾部切 40%（`cut_point = end - remaining*0.4`，必然 > 原段 position_to_write，无冲突）。
3. 原慢线程 `end` 被缩小、无感知。用 `std::sync::Mutex` 短临界区（不跨 await）保护段表。

**慢线程三层检测**（`detector.rs`）：Layer1 `avg < median(peers)×0.3` → Layer2 连续 3 周期 → Layer3 P10 确认 → kill（归还段 + 换源重试）。新线程 2s 宽限期，样本不足 6 次不判。

**限速**（`rate_limit.rs`）：全局令牌桶，10ms 粒度，最多攒 1 秒。

**续传**（`resume.rs`）：`{urls, total, segments:[{start,end,written}], sha256, options}` 写 JSON 控制文件（`<文件名>.gkdl`），每 ~1s 或段事件时保存；启动时若存在则按 `written` 续传。mmap 写盘 + 控制文件双写。

**校验**（`hash.rs`）：全部完成后流式读文件算 SHA-256，与期望值比对，不符报错（RPC `errorCode=32`）。

## 4. 下载后自定义脚本（Post-Download Hook）

**行为定义**：
- **时机**：任务成功完成且 SHA-256 校验通过后运行；下载失败/校验失败不运行。
- **退出码**：仅记录日志，不影响任务状态。
- **配置**：仅全局配置，位于 daemon 配置文件（`config.rs` 的 `hook` 段）；CLI 直连模式用 `--post-script <path>` 指定。
- **超时**：默认 60s，超时则终止脚本并记 warning 日志。
- **输出**：stdout/stderr 逐行写入 `tracing` 日志。

**传递信息**：
- 命令行参数：`<script> <下载文件绝对路径>`
- 环境变量：`GKDL_URL`、`GKDL_GID`、`GKDL_SIZE`、`GKDL_SHA256`
- 用 `tokio::process::Command`（不阻塞任务管理线程）；`.ps1` 用 `powershell -ExecutionPolicy Bypass -File` 执行，其余直接执行。

**模块归属**：`src/app/hooks.rs`（`run_post_download_script(ctx)`），`task_manager.rs` 在任务进入 `complete` 状态后调用。

## 5. 日志模块（`src/app/logging.rs`）

参考 `rime_sync/客户端/core/logs.py` 逻辑：

1. **格式**：`YYYY-MM-DD HH:MM:SS,mmm - <target> - <LEVEL> - <message>`，自定义 `FormatEvent` 对齐参考脚本。
2. **双输出**：日志文件 + stdout（stdout 按 TTY 判断是否启用 ANSI）。
3. **写盘**：实现 `MakeWriter` 的 `RotatingFileWriter`（内部 `Mutex<File>` + 当前大小计数）：
   - 写入超过 `max_size_mb` → 轮转：`gkdl.log → gkdl.log.1 → … → gkdl.log.N`，丢弃最旧（对应 `backup_count`）。
4. **启动归档**（`archive_enabled=true` 时）：
   - 扫描 log 目录下 `gkdl.log*` 且 **mtime 日期 ≠ 今天** 的文件 → 视为昨日日志。
   - 打包进 `logs/archive/logs_<YYYYMMDD_HHMMSS>.tar.xz`（xz2 优先）→ 失败则 `.tar.gz`（flate2）→ 再失败则纯 `.tar`。
   - 归档成功后删除原文件；单个失败不阻断后续。
5. **保留清理**：`archive/` 下 mtime 早于 `retention_days` 的归档删除。
6. **入口**：`init_logging(config_dir, &LogConfig)` 在 `main` 最早调用；日志路径相对配置目录解析。

## 6. 任务管理（`task_manager.rs`）

- `HashMap<Gid, Task>`，Gid 为 16 位 hex（aria2 风格）。
- 任务状态机：`waiting/active/paused/error/complete/removed`。
- 提供 `tellStatus` 所需全部字段（字符串化数值）：`totalLength/completedLength/downloadSpeed/connections/errorCode/files[]` 等。
- 事件广播：任务状态变化 → 供 RPC WS 推送 `aria2.onDownloadStart/Complete/Error/Pause/Stop`。
- 任务进入 `complete` 后触发 post-download hook。

## 7. 配置文件（YAML）

默认 `%APPDATA%\gkdl\config.yaml`，`--config` 可覆盖。优先级：默认值 < 配置文件 < CLI 参数。

```yaml
daemon:
  host: 127.0.0.1
  port: 6800
  rpc_secret: ""
  no_tray: false
download:
  split: 8
  min_split_size: 262144     # 字节
  max_speed: 0               # 0=不限
  retries: 3
  timeout: 30
log:
  level: info
  file: logs/gkdl.log         # 相对配置目录解析
  max_size_mb: 10
  backup_count: 5
  archive_enabled: true
  retention_days: 90
hook:
  post_download_script: ""
  timeout_sec: 60
```

CLI 直连模式可无配置文件。

## 8. JSON-RPC 服务（按《aria2 AriaNg 兼容 JSON-RPC 规范》）

- **传输**：HTTP POST `/jsonrpc`（Content-Type `application/json-rpc`）、GET JSONP（`method/id/params(BASE64)/jsoncallback`）、WS `/jsonrpc`（text frame）、CORS 预检（回显 `Access-Control-Request-Headers`）。
- **协议铁律**：`id` 原样回传；数值/布尔一律字符串（仅 `error.code`、`jsonrpc`、`id` 例外）；`params` 仅数组；未知方法 code=1；缺 id → -32600；鉴权失败延迟 1s 返回 400。
- **token**：`params[0]` 为 `token:xxx`，恒定时间比较。
- **方法**（AriaNg 常用集）：`getVersion, addUri, tellStatus, tellActive, tellWaiting, tellStopped, getGlobalStat, pause/pauseAll, unpause/unpauseAll, remove/forceRemove, purgeDownloadResult, removeDownloadResult, getOption/getGlobalOption, changeOption/changeGlobalOption, changePosition, shutdown, forceShutdown, getSessionInfo, saveSession` + `system.multicall/listMethods/listNotifications`。
- `system.multicall`：成功项为单元素数组，禁止递归。

## 9. 托盘与守护

- 独立线程跑 `winit` 事件循环 + `tray-icon` 托盘图标。
- 菜单：打开状态页（本机内嵌极简 HTML 状态页 `/`）、暂停全部、继续全部、退出（graceful shutdown，3s 后退出对齐 aria2）。
- 与 tokio runtime 通过 channel 通信（暂停/退出命令）。

## 11. 里程碑

1. **M1 下载核心**：config/segment/scheduler/detector/rate_limit/source/worker/mmap_writer/engine —— CLI 单 URL 下载跑通（含限速、多线程）。
2. **M2 续传 + 校验**：resume.rs 控制文件、hash.rs；中断重启续传验证。
3. **M3 任务管理 + hook**：task_manager + GID/状态/进度统计 + 下载后脚本。
4. **M4 JSON-RPC**：protocol/server/methods；用 AriaNg 实测连接、添加、进度、暂停、完成。
5. **M5 daemon + 托盘 + 配置 + 日志**：后台模式、托盘菜单、状态页、YAML 配置、日志归档。
6. **M6 打磨**：多源容错降级验证、错误码映射、文档、测试。

## 12. 测试计划

- **单元测试**：切片计算、工作窃取切尾不冲突、三层检测判定、令牌桶限速。
- **集成测试**：本地 HTTP 测试服务器（支持 Range）+ 写日志的测试脚本，验证"完成后触发/失败不触发/超时终止"。
- **验证清单**：按《aria2 AriaNg 兼容 JSON-RPC 规范》§12 逐条验证 RPC 兼容性。

## 13. 关键设计决策汇总

| 决策点 | 结论 |
|--------|------|
| 配置格式 | YAML（`serde_yml`） |
| 日志输出 | 文件 + stdout 双输出 |
| 日志归档压缩 | `.tar.xz`（xz2）→ `.tar.gz`（flate2）→ `.tar` |
| 写盘方式 | mmap（`memmap2`）首选 |
| 下载后脚本 | 仅成功后运行；退出码仅记日志；全局配置；60s 超时 |
| RPC 端口 | 6800（AriaNg 默认）；secret 空 |
| 状态页 | 内嵌极简 HTML，不打包 AriaNg |
